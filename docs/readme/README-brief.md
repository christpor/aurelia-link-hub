# README Brief — Aurelia Link Hub

## Reader and job

The primary reader is a brand developer or collaborator evaluating the public source. Their first job is to understand that this is a **static link-in-bio prototype**, view the live interface, and run the supported local development path without assuming that placeholder links, commerce data, analytics, or email processing are already connected.

## Architecture and content decision

The source evidence classifies this repository as an **application-source-distribution** project. The README will open with bounded positioning and the live site, then offer a small local command path, a project map, the Vercel static-hosting configuration, and explicit prototype boundaries. It will defer the release audit and detailed production evidence to the existing POR and release files.

| Decision | Rationale |
|---|---|
| Use no visual | No repository-controlled screenshot is required to complete the reader’s decision; the live link is the authentic product surface. |
| Show four pnpm commands | The manifest defines the development, type-check, build, and preview scripts. |
| Include prototype boundaries prominently | Source and release evidence show placeholder URLs, non-transmitting newsletter behavior, and no configured analytics provider. |
| Include a license note rather than an MIT badge | The manifest declares MIT, but no top-level license text was found. |

## Selected and delegated sections

The README will contain the project description, live link, included interface behavior, local commands, project map, deployment note, prototype boundary, documentation links, and license note. It will not include a generic feature inventory, badges, generated visuals, a fictional API integration guide, a security policy, or contribution instructions because the repository does not provide authoritative material for those sections.

## Open review items

The brand owner should replace the placeholder destinations and product data, select providers for analytics and newsletter delivery, and add an authoritative license file before relying on the manifest’s license declaration for distribution decisions.
